# Changelog

All packages version together. Entries are generated from changesets on release; this file also records protocol-level changes by hand.

## 1.1.0

Per-package entries are in each package's CHANGELOG.md. Protocol and contract changes:

- `spec/SURFACE.md` [S-WEB-6]: a host that runs the page for a person (headless) may install an approver before page code, at `INJECTED_APPROVER_GLOBAL`; the WebMCP adapter asks it before the page's own approval UI, and the host asks the person through a channel the agent cannot answer.
- [S-WEB-7]: the WebMCP adapter's domain granularity, a fixed tool set taking entry ids; [S-WEB-2]: the observe tool filters and pages, and every acting tool states `consequentialHint` both ways.
- [S-AUTO-7]: controls named for items among their peers (tenants, tables), and filter strips, are low risk; a popup a dialog's trigger opened belongs to that dialog wherever it is rendered; `_` joins a word.
- [S-AUTO-14]: a listing rendered as buttons, or with a button per row, is read as content, one item per row; `display: contents` is not hidden.
- The agent web (experimental, `docs/agent-web.md`): agent pages are Markdown with opaque, single-use, revision-bound links `/s/<session>/<link>`; the site's agent pages are `/agent`, `/agent/signin?agent_session=<id>`, `/agent/approve/<id>`, and `/agent/input/<id>`, and the site reports what the person did over `/api/sessions/…` and `/api/pending/…` with `Authorization: Bearer <secret>`. Every agent page is `Cache-Control: no-store, private`.
- `agentEntry` answers a GET for a document from a recognized agent (`agentBrowsers`, or any request with `Signature-Agent`) arriving from outside the site (`Sec-Fetch-Site` not `same-origin`/`same-site`) with a 303 to `/agent`; `?agent=off` opts out.
- [S-AUTO-7]: an item block with no peers whose leading text is an identifier opens that item (low risk, navigation).
- `@summationai/axe-relay`'s peer dependency on `@summationai/axe-mcp` is a caret range (`^1.1.0`), so a minor release of the group no longer reads as breaking it.

## 1.0.0

Initial release of the Body Spray SDK and the `axe/0.1` protocol, published to the summationai organization's GitHub Packages registry.

- The packages are `@summationai/axe-*` (formerly `@axe/*` in the repository) and the CLI package is `@summationai/axe` (formerly `axe`); the commands keep their names (`axe`, `axe-host`, `axe-relay`). GitHub Packages serves only the scope that matches the owning account.
- Every package versions together from 1.0.0; the pre-release work below was recorded as 0.1.0 and never published.

### Request policy (review item 6)

- Protocol §6.4, [P-TRANS-1] to [P-TRANS-4]: a `POST` to a state-changing endpoint (an action that is not `readOnly`, `/axe/continue`, `/axe/resume`) must be `application/json` or `application/*+json`, else `unsupported`; a `POST` carrying ambient credentials from an origin that is neither the site's (from `baseUrl`, never `Host` or forwarded headers) nor trusted is `forbidden`, the same response for every path; requests with neither `Origin` nor `Sec-Fetch-Site` pass the origin rule.
- `@summationai/axe-core`: `createAXE({ requestPolicy: { requireJsonContentType, trustedOrigins, originCheck } })`, applied at the entry of `handle()` before any body, identity, or token is read. Defaults: JSON required on writes; origin checked on any `POST` with a `Cookie` header; origins with credentialed `cors` trusted. Refusals carry `details.reason` `json_required` or `cross_origin_refused`. Pure functions exported (`evaluateRequestPolicy`, `resolveRequestPolicy`, `isJsonContentType`, `isAcceptedOrigin`). Migration: a caller that posts JSON to a mutating action without `Content-Type: application/json` now gets `unsupported`; `@summationai/axe-client`, `@summationai/axe-mcp`, and the conformance suite already send the header.
- `@summationai/axe-express` and `@summationai/axe-next` (Pages): the adapters keep the `Content-Type` the client sent instead of relabeling a parsed body as JSON, and the Express adapter reads the raw stream while it is unread (Express 4 leaves `req.body = {}` on a body its json parser skipped).
- `@summationai/axe-testing`: conformance check `runtime.json-content-type`.

- `spec/SURFACE.md`: the Surface contract (v0.2), ported from the sumapps trials and rewritten on top of the AXE envelope: live controls with `state.reason`, `effect` as AXE risk metadata, one revision per application, refusals as `conflict` / `not_found` / `invalid_input` / `unavailable`, and `requires` (AXE kinds) plus `handoff` on unavailable controls.
- `@summationai/axe-surface`: `createSurface` (registry, `observe`, `act`, revision, ledger, `expose`), `@summationai/axe-surface/react` (`useSurface`), and `@summationai/axe-surface/axe` (`surfaceActions`: any surface becomes an AXE manifest with `<ns>.observe`, `<ns>.ledger`, and one action per entry, refusals mapped onto the ladder, `continue` running the application's `fulfill`).
- Vocabulary: a "Surface" section in `spec/VOCABULARY.md` (entry kinds, ops, field names, API names) so the drift test covers the new package.
- Two defects from the first staging trial pinned as contract rules with tests: `act` refuses any `target` that is not a non-empty id or a non-negative integer index as `invalid_input` before any lookup, an index never resolves to a row without one, and the revision guard runs before resolution ([S-ACT-6..8]); applications must re-register on transient states ([S-REV-5]), with `freeze(reason)` / `thaw` as the first-class helper: every entry unavailable with the reason, `observe().frozen`, acts `unavailable`, revision moved on both ends, nested freezes counted ([S-FRZ-1..4]).
- DOM mirror: `surfaceAttributes`, `surfaceSelector`, and `describeEntry` in `@summationai/axe-surface`, and `useSurfaceProps` in `@summationai/axe-surface/react`, so the accessible name a browser agent or screen reader reads is the entry name by construction. Spec §7 is now a rule set: [S-DOM-1] (name wording and the attribute set), [S-DOM-3] (the selector contract), [S-DOM-4] (the one-line description); a `domAttribute` vocabulary category names the attributes.
- Ledger (`spec/SURFACE.md` [S-LED-1..7]): every `act`, run or refused, appends `{ seq, at, op, target, actor, revBefore, revAfter, status, text?, changed }`; `ledger({ since, actor, limit })` reads it oldest first under bounded retention (`ledger.max`, default 1000); `observe()` carries `ledgerSeq` and every act result its `seq`; `expose` publishes `ledger`. The bridge adds `<ns>.ledger` (read-only, with `display`) and emits one action event (`surface.act`) per act on the server's `onActionEvent` sinks ([S-AXE-4]). In `@summationai/axe-core`: action events (`spec/EVENTS.md` [E-5..7], `schemas/action-event.schema.json`), `emit` on the handler context, `onActionEvent` on `createAXE`, and `consoleSink`/`jsonlFileSink` accept them.

### Live state

- Protocol §21 (additive, still `axe/0.1`): a site MAY publish a revision. Every result envelope gains optional top-level `rev`; requests to `/axe/actions/{name}`, `/axe/continue`, and `/axe/resume` gain optional `expectedRev`; a stale `expectedRev` is `conflict` with `details: { expectedRev, currentRev }` and nothing applied, checked after the idempotency replay and before the handler or a login handoff. Actions gain optional `availability` (`{ available, reason?, requires?, handoff? }`), the manifest gains `live: { rev?, url? }`, and `GET /axe/state` serves `{ rev?, actions }` per caller with `Cache-Control: no-store`. `unavailable` errors MAY carry `details: { reason, requires?, handoff? }`. Rules P-LIVE-1 to P-LIVE-10; `spec/schemas/state.schema.json`.
- `@summationai/axe-core`: `createAXE({ revision })`, `action({ availability })`, handler context `availability` and `expectedRev`, `unavailable()` helper, `describeLive()`, lint rule `unavailable-without-reason`.
- `@summationai/axe-client`: `expectedRev` on `invoke`, `continue`, `resume`, and `run` (tracked through the ladder), `state()`, `live()`, `stateToMarkdown`; `present` carries `rev` into `toMarkdown` and `toHTML`.
- `@summationai/axe-mcp`: `axe_state` tool when the manifest carries `live`, `expectedRev` argument on action tools, availability in tool descriptions, stale `conflict` and `unavailable` explained.
- `@summationai/axe-testing`: six `live.*` conformance checks (skipped without `live`), audit check `actionable.live-state`.
- `@summationai/axe-surface`: a stale act's `details` are `{ expectedRev, currentRev }` (was `{ rev, expectedRev }`); `surfaceActions` reads the envelope's `expectedRev`; pass `revision: surface.currentRev` to `createAXE`.

### Surface: integration fixes (contract v0.4)

What the first integration into a legacy-DOM application asked for, made general.

- Browser bundling: `jsonlFileSink` moves to `@summationai/axe-core/node`, the one entry of `@summationai/axe-core` that needs Node; it is no longer exported from `@summationai/axe-core` or `@summationai/axe-core/events`. A browser bundle importing `@summationai/axe-surface` no longer meets `fs/promises`. New zod-free subpath `@summationai/axe-core/json-schema` (`validateJsonSchema`, `schemasStructurallyEqual`, `deepEqual`). A bundle test in `packages/surface/test` builds `@summationai/axe-surface` plus `@summationai/axe-surface/react` for the browser with esbuild and fails on a Node built-in, on Zod, or above 50 kB minified (about 21 kB today, from a build that failed and, with the built-in aliased away, 515 kB).
- Zod-free surface ([S-ENT-3]): `@summationai/axe-surface` and `@summationai/axe-surface/react` import nothing that carries Zod. `edit.schema` is a JSON Schema or a Zod schema; a Zod schema is detected structurally (`safeParse`), validated by calling it, and published in `observe()` through `createSurface({ toJsonSchema })` (pass `toJsonSchema` from `@summationai/axe-core`), which the `requires` schemas from `accept()` need too. Registering a Zod schema without the converter throws with that instruction. `@summationai/axe-surface/axe` still carries Zod through `@summationai/axe-core`.
- Revision modes ([S-REV-1], [S-FRZ-2], [S-FRZ-3]): `surface` (the application calls `bump`) or `app` (it adopts a server revision with `setRev`), inferred from the last call or pinned with `createSurface({ revision })`; `revisionMode()` reports it. In `app` mode `freeze` and `thaw` leave the revision alone and still report the freeze and notify `onChange`, so an act planned before a freeze is `unavailable` while frozen and accepted after the thaw exactly when the application's revision did not move.
- Handler reports ([S-ACT-1], [S-LED-5]): a handler, `edit.set`, or `more` may return `{ changed?, rev? }`; `act` folds `changed` into the output and the ledger and adopts `rev` as `setRev` would before building the result. `HandlerReport` type.
- Live DOM mirror ([S-DOM-1]): `surface.attributesFor(id)` returns `{ set, remove }` from the live availability, so a freeze shows with its reason and a stale reason is removed; `SURFACE_ATTRIBUTES` lists every attribute the mirror may set. `surfaceAttributes(entry)` stays for a one-time render. `useSurfaceProps` follows the live availability and re-renders when it changes.
- Bridge ([S-AXE-2], [S-AXE-6], [S-LED-1]): a collection without `more` has no action (it stays a row of `observe`); entry input schemas describe the shape only (`text` a string, `confirm` an optional boolean), leaving `maxLength`, the field's schema, and a required `confirm` to the surface so every such refusal is ledgered and emitted; `needs_human` only for a handoff with a `url`.
- Handoff without a `url` ([S-AV-3]; protocol [P-LIVE-5], [P-LIVE-9]): `HandoffSpec.url` is optional on an unavailable action's `handoff`, for a step taken inside the application with no page of its own. It is reported in `availability` and in `error.details.handoff` and never becomes `needs_human`, whose Handoff stays complete ([P-HAND-1]). `spec/schemas/state.schema.json` and `manifest.schema.json` follow.
- `createAXE` defaults `auth` to `{ modes: ["none"] }`; an explicit empty `modes` is refused with a message that says to omit `auth` for a public site.
- Consuming from a checkout: `scripts/pack-for-consumer.sh <out-dir>` builds and packs core, surface, client, and testing and writes a `SOURCE` file; `docs/deploying.md` ("Consume from a checkout") covers `file:` dependencies, the overrides for packed siblings, and copying tarballs into place before installing from a lockfile.
- Vocabulary: `attributesFor`, `revisionMode`, `SURFACE_ATTRIBUTES`; `jsonlFileSink` now under `@summationai/axe-core/node`.

### Surface: write preconditions (contract v0.5)

- Ordering ([S-ACT-9]): acts on one surface run one at a time, in call order. Every pre-handler check runs when `act` is called, so a refusal never waits; an act that waits behind another is checked again when it reaches execution (revision, target, freeze, availability), and is `conflict` or `unavailable` with no handler run when a predecessor's commit, a person's `bump` or `setRev`, or a freeze intervened. Before, two asynchronous acts presenting the same `expectedRev` both ran and both returned `ok`. `observe`, `availability`, and `ledger` do not wait.
- A commit that leaves an app-owned revision in place ([S-ACT-10]) closes the claims taken before it at that revision, unless it provably changed nothing (`changed: []`); an act claimed after it is accepted.
- The handler's own precondition ([S-ACT-11]): handlers, field setters, and `more` receive an `ActContext` (`{ id, op, expectedRev, actor }`) as their last argument for a conditional write, and refuse by throwing `SurfaceConflict` (new export) or returning `{ conflict: { currentRev? } }` in the `HandlerReport`; `act` returns `conflict` with `details.currentRev`, ledgers a refusal, and adopts nothing.
- A stale handler report ([S-REV-6]): a reported `rev` lower than the surface's revision when the handler settles is not adopted; the ledger entry carries it as `ignoredRev` (also in `<ns>.ledger` output).
- Bridge ([S-AXE-4]): the entry action passes the envelope's `expectedRev` to the queued act, so the server's check is the first gate and the surface's the second; a test drives two concurrent invocations through `axe.handle`.
- Vocabulary: `SurfaceConflict`, `ActContext`, `ignoredRev`, the handler report's `conflict`.

Options `auth`, `read` (observe and ledger), `authFor(entry)`, `template`, `redactEvent`. `surfaceActions` accepts a resolver `(context) => Surface | null` in place of a surface, with a `template` for the action set; `scopedSurfaces({ create, key, max, idleMs, now, onEvict })` builds one keyed by tenant and principal. Availability for an unidentified caller never reads a protected surface. Types `SurfaceContext`, `SurfaceResolver`, `ScopedSurfaces`, `ScopedSurfacesOptions`.
- `@summationai/axe-surface`: field entries take `sensitive: true` (no `value` in `observe()`, `describeEntry` says `value hidden`, no ledger text); `createSurface({ ledger: { text: "keep" | "hash" | "omit", redact } })`; ledger entries may carry `textHash`. ### Surface: mounted React behavior (contract v0.6)

- `@summationai/axe-surface/react`, `useSurface` and `useSurfaceProps` (review item 11): the registration belongs to the entry's `id` and the target surface. A change of either unregisters the previous pair and registers the new one; before, an id change left the old id registered (and unmount then removed the old id, leaving the new one), and a target change registered nothing in the new surface. An act now runs the latest render's `handler`, `edit.set`, `more`, and `requires.fulfill` through a stable wrapper, whatever `deps` list; before, it ran the closure from the render that last changed `deps`. Registration runs in a layout effect (a passive effect on the server). `useSurfaceProps` subscribes once rather than on every render.

### Unattended mode: `@summationai/axe-host` (the default for an agent outside the browser)

- New package `@summationai/axe-host`: `createHost({ appUrl, startPath?, sessionFor?, relay?, browser?, maxSessions = 20, idleMs = 15 min, navigationTimeoutMs, allowedOrigins?, restrict?, tokenTtlSeconds?, agentAuth?, protectedResource?, dev?, onEvent? })` runs the application in headless Chromium (`playwright-core`, a dependency of this package only) for each principal and tenant an agent authenticates as: one shared browser, one isolated browser context per identity, started on the agent's first tool call, ready when the page's surface is connected to the relay. ### Easy mode: derived surfaces (Surface contract v0.9)

- `@summationai/axe-surface/auto` (new subpath; browser, no Zod, no Node built-ins, shares the main registry): `autoSurface({ root, surface, config, observe, expose, route, hidden, revision, layout, now })` reads the rendered page's accessibility semantics and registers one entry per control, keeps it current with a coalesced `MutationObserver` (open shadow roots and same-origin frames included), acts through the events a person causes (pointer, mouse, focus, `click()`; the native value setter plus `input` and `change`; `beforeinput` and `insertText` for rich-text editors; load-more by button or scroll), waits for the page to settle, and reports `changed` and `notices` (toast and status text). The handle has `refresh`, `coverage`, `configure`, `config`, `approve`, `elementFor`, `metaFor`, `route`, `expose`, and `stop`.
- `SurfaceConfig`: a plain, reviewable overlay of rules matched by key, `data-surface-id`, selector, or route, role, and name, setting name, object, role, id, reason, state, effect, sensitive, editable, hide, approval, group, or a real `handler` (the declared tier); plus routes, lexicon, policy, groups, sensitive and exclude selectors, declared entries, landmarks, and navigate. `checkConfig` validates it.
- Safety defaults: a heuristic risk per derived action from role, words (destructive words anywhere; view and commit words in the verb position), styling, and surroundings, erring high; the default policy asks the person before a high-risk act, through an unavailable state with an `approval_required` handoff, and `handle.approve(id)` records the person's approval for one act. Sensitive fields (passwords, card fields, one-time codes) never report a value and are read only to agents.
- Coverage: `handle.coverage()` and `formatCoverage` report counts by kind, tier, and name confidence, approvals, gaps (unnamed and icon-only controls, duplicates, clickable elements without a role, canvas and chart regions naming the library, cross-origin frames, virtualized grids, file inputs, closed shadow roots, unrecognized effects), stale configuration, and a rule to paste per gap.
- `autoActions` in `@summationai/axe-surface/axe` (with `autoDomains` in `/auto`): generic tools for a derived surface (groups, `navigate`, `set-field`, `run-control`, `load-more`), the same size on every page.
- `@summationai/axe-surface/react`: `SurfaceProvider`, `useAutoSurface`, `useAutoSurfaceHandle`; starts in an effect, re-scans on History API and router location changes, stops on unmount. Tested on React 18 (the package) and React 19 (`examples/auto-react19`).
- `@summationai/axe-surface`: entries carry an optional `source` (`derived`, `annotated`, `declared`), reported on observe rows that are not declared; an action entry may carry a `value` (`{ checked }`, `{ pressed }`, `{ selected }`, `{ expanded }`); a handler report may carry `notices`, returned in the act's output.
- `spec/SURFACE.md` §10 ([S-AUTO-1] to [S-AUTO-13], [S-CFG-1] to [S-CFG-8]); `docs/auto-surface.md`; vocabulary rows under "Derived surfaces"; a headless browser check (`pnpm --filter @summationai/axe-surface test:browser`).

- Naming: a surface entry's guarantee tier is `tier` (`derived` or `annotated`; absent means declared), distinct from a ledger entry's `source` (`application` or `server`). Both were added in this unreleased cycle under the same name; the entry field was renamed before release.
### Integration in four steps: `axe surface init`, `axe surface coverage`, and the prompt pack

- `axe surface init [--dir] [--framework auto|react-router|next|vite-react|react|plain] [--mount <file>] [--flag <NAME>|<module>#<export>] [--flag-hook <call> --flag-import <module>] [--relay <url>|--relay-dev] [--dry-run] [--yes] [--install] [--vendor <dir>]`: detects React Router 7 (`app/root.tsx`, honoring `appDirectory`), the Next App Router (`app/layout.tsx`), Vite React and React under any bundler (the entry that calls `render()`), and plain HTML (`index.html`), and the package manager from the nearest lockfile (npm, pnpm, Yarn classic, Yarn Berry workspaces with their root, bun). Writes a surface component (`surface.tsx`, or `surface.js` for a plain page) and an empty `surface.config` overlay with commented examples beside the root, and wraps the root (or a `--mount` layout; layout routes are listed as candidates) in one import and one element in the file's own quotes, semicolons, and indentation. Gated by default on a build-time variable (`VITE_SURFACE`, `NEXT_PUBLIC_SURFACE`; on in development, off in a production build), or on localhost for bundlers without one; `expose` only in development. Prints a unified diff, applies with `--yes` or after a prompt, and is idempotent. Never adds a dependency unless `--install`; prints the registry and the tarball install forms, including the `overrides`, `pnpm.overrides`, or root `resolutions` entry.
- `axe surface coverage <url> [--auth] [--routes] [--max-pages] [--wait] [--playwright-from] [--json] [--out]`: loads Playwright lazily from the app (or prints how to install it), waits for `window.__surface`, calls `coverage()` on each listed route or up to five same-origin pages (never a sign-out link), and prints one Markdown report with each page's gaps and suggestions and the top gaps across pages. A page without `coverage()` but with `observe()` gets a basic count from the CLI; a page without a surface says why (not mounted, flag off, production build, `expose` off, a login redirect).
- `axe surface prompt` prints `packages/cli/templates/integrate-surface.md`, the integration prompt a coding agent runs in any app: dry run, review, apply, install, measure, write config for the top gaps, verify by driving the app. It names the `llms.txt` sections it relies on; a test checks they exist.
- The generated code imports `SurfaceProvider` from `@summationai/axe-surface/react`, `SurfaceConfig` and `autoSurface` from `@summationai/axe-surface/auto`, and `connectRelay` from `@summationai/axe-relay/client`, which land separately; `packages/cli/src/surface/api.ts` holds every guessed name and prop in one place, and the fixture typecheck stubs pin the guessed shapes.
- Vocabulary: `axe surface`, `axe surface init`, `axe surface coverage`. Docs: `docs/getting-started.md` starts with "Add Surface to an existing app in four steps".
- CI runs on Node 22 and 24 (was 20 and 22): jsdom, which the browser-style tests use, requires Node 22 or later. The workspace now requires Node 22 to develop. Published packages keep their declared Node range, but it is no longer tested on Node 20.
- Security fix found by an end-to-end trial: an auto-derived surface read the relay's in-page indicator, so its Stop, Approve, and Deny were controls an agent could see, and a pending approval moved the revision so the agent's act came back stale. The scan now skips any subtree marked `data-surface-ignore` and the relay indicator itself; the relay marks its indicator.
- Derived surfaces move the revision only when something an agent can act on changes (a control appears, disappears, or changes name, availability, or value), not when a table's content does, so a page that polls or updates live does not refuse every act.
- Act notices from the top-level heuristic report only text that was not on the page before the act, so a page re-rendering its own rows is not reported as a message.
- One approval, not two: an auto-derived surface registers its approver on the surface (a shared symbol), and the relay treats a derived approval gate as needing the person's approval and grants it when the person approves in the tab. Granting or expiring an approval does not move the revision, so the agent's retry at the same revision runs.
- `@summationai/axe-relay`: `@summationai/axe-mcp`, `@modelcontextprotocol/sdk`, and `ws` are optional peer dependencies, needed only where a relay server runs. A browser application that imports `@summationai/axe-relay/client` installs none of them (verified with Yarn 4 under a seven-day registry age gate; the app's browser bundle of `@summationai/axe-surface/react`, `/auto`, and `@summationai/axe-relay/client` is about 99 KB minified with React external, and every entry imports cleanly in Node for server rendering).

### Easy mode: reading the page and waiting for slow work (Surface contract v0.9, [S-AUTO-14] to [S-AUTO-16])

- `@summationai/axe-surface/auto`: `handle.read({ region, query, maxChars, maxRows, cursor })` returns the content the page shows the person as sections by heading (`{ heading, level, text, fields, tables, lists, opaque? }`), with alerts and toasts in `notices`. Sections fall back to dialogs, named regions, sectioning elements, and cards with a title-like first child on landmark-less pages; fields come from `dt`/`dd`, row-header tables, `aria-labelledby`, `aria-describedby`, label and value leaves, "Label: value" lines, progress bars, and form controls; tables from native tables and ARIA grids (ag-grid rows joined by `aria-rowindex` across pinned containers, open shadow roots included, virtualized totals from `aria-rowcount`); editor text from ProseMirror and Tiptap. Charts, canvases, closed shadow roots, and cross-origin frames are reported by title only. Sensitive fields keep their label and lose their value, configured `sensitive` selectors are withheld whole, and `data-surface-ignore`, the relay's indicator, `exclude`, and the new `read.exclude` are never read. Bounded (50 rows, 12000 characters by default) with a cursor that splits long sections. `formatRead` renders Markdown. `read.regions` in `SurfaceConfig` names regions by selector.

- `@summationai/axe-relay`: `surface_read` and `surface_wait` by default (`content: false` leaves them out); new `read`, `wait`, and `content` messages carry them to the tab, whose auto surface answers; the mirror translates revisions both ways. `RelayOptions.domains` takes `DomainSpec[]`.
- Coverage: `unreadable` and a "Content an agent cannot read" section in `formatCoverage`.
- Act notices never come from a `data-surface-ignore` subtree or the relay's indicator (found while testing wait: an application's own agent panel answering would have been reported to the agent as a notice).
- The `@summationai/axe-surface/auto` browser bound is now 120 kB minified and 43 kB gzipped (was 100 and 35), and `SurfaceProvider`'s 44 kB gzipped (was 36): the reader and the waiter add about 26 kB minified, 9.5 kB gzipped.

### Relay: an act whose page unloads is not "nothing applied" ([S-RELAY-14])

- Bug: an act whose click navigated the page (a link, a form that posts and reloads) lost its connection mid-act; the relay answered a retryable `unavailable` (`tab_disconnected`), the MCP bridge's client retried it a second later against the new page, and the agent was told `conflict`, "Nothing was applied", although the click had run. Reproduced in Chromium through `@summationai/axe-host` (a link and a form post) and in jsdom.
- `@summationai/axe-relay/client`: when the page begins a navigation (`beforeunload`, then `pagehide`) while an act runs, the tab answers the act before its connection closes: `ok` with `navigated: true`, `changed: []`, a notice to observe the new page, and a ledger line. Reliable in headless Chromium (12 of 12 runs, link and form post).
- `@summationai/axe-relay/server`: any other act the tab does not answer (the page crashed or closed, or `actTimeoutMs` passed, also after an approval) is `unavailable`, `retryable: false`, `details: { reason: "outcome_unknown", cause: "tab_disconnected" | "tab_timeout" }`, "The act was sent and may have taken effect. Observe before acting again". Not retried by the SDK.
- `@summationai/axe-core` ([P-OP-3] amended): an `error` whose `details.reason` is `outcome_unknown` is stored under its idempotency key like a success, so a retry with the same key is answered with it and never runs the work twice. `@summationai/axe-mcp` explains the reason in the tool text. `@summationai/axe-surface`: `ActOutput.navigated`. Vocabulary: `outcome_unknown`.
