Agents are becoming the front door to every website.

AXE is an open, HTTP-native protocol and TypeScript SDK that lets your site declare what it can do, how to present results, what it needs to finish, and when a human must step in. You wrap functions you already have.

The problem

Today the agent gives up and hands the task back.

The same request, twice: once against a website as it is, once against a website that declares what it can do.

Without AXE

Apply for the one-bedroom at The Meridian in Bellevue and pay the holding deposit from my checking account.

Agent opens a headless browser and starts the six-page application.

I found the unit and filled in the first pages, but the deposit form wants bank details typed into a widget I can't safely use, and I can't tell whether submitting charges you. I couldn't complete this. Please finish it yourself.

With AXE

Apply for the one-bedroom at The Meridian in Bellevue and pay the holding deposit from my checking account.

Agent calls applications.submit; the site answers needs_input accepting payment.ach-debit.

Oakridge needs a $500 refundable deposit by bank transfer. Use your checking account ending 4471?

Yes.

Agent continues with the authorization from its wallet; the site answers ok.

Done. Application APP-8812 is submitted and the deposit is received.

How it works

The ladder: complete, ask the agent, then the human.

When an action cannot finish, the site says exactly what would unblock it, in a form the agent may already hold. Only when nothing matches does it hand off to the human, with a URL, a reason, and a token to resume. Every envelope below is real: the build runs the docs' apartment example and records what came back.

What you declare

Six things a site gives an agent.

Manifest

One JSON document at a fixed path: who you are, what you can do, how to authenticate, what the rules are.

Actions

Typed operations with schemas, a description written for a model, and truthful risk, readOnly, idempotent, and reversible metadata.

Display

Which fields matter when a user compares results, where the human page is, and the disclaimer that must accompany any rendering.

Affordances

What can be done with each result, with inputs pre-bound. The user's pick becomes the next call with no guesswork.

Requirements and kinds

Ask the agent first: a shared vocabulary of payloads a wallet or credential store can supply.

Handoff

The human, last: a URL that lands on the step, plain instructions, and a token to resume.

Mount it

Then three commands

npx axe init

Writes an axe.ts with one read-only action and the mount file for your framework.

npx axe conformance http://localhost:3000

Runs the protocol suite against your server and prints a pass/fail table. This is how you know you are done.

npx axe mcp http://localhost:3000

Serves your site to Claude Desktop or Claude Code as an MCP server, one tool per action.
